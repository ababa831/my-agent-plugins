# Git開発共通ルール

- コミットメッセージは [Conventional Commits](https://www.conventionalcommits.org/) に従う。
- 1コミットには一つの目的だけを含め、関係のない変更を混ぜない。
- `main` へ直接コミットまたはpushせず、作業ブランチからPull Requestを作成してマージする。
- TDDを基本とし、変更に対応するテストを先に追加または更新する。
- 完了前に、リポジトリで定められたテスト、lint、formatを実行する。
- READMEは日本語版を `README.md`、英語版を `README.en.md` として管理する。
- シークレット、認証情報、個人情報をコミットしない。
- 曖昧な実装判断は、既存コードと公式文書を根拠に決める。
- 応急処置ではなく根本原因を修正し、必要以上に複雑な実装を避ける。
- 細部の完成度に偏らず、指示者が本当に求めている成果の達成を最優先する。
- 制約によって要求どおりの達成が困難になった場合は、制約を独断で緩和せず、実行可能な対応候補と各候補のトレードオフを示して指示者の判断を仰ぐ。
- リポジトリ固有のルールは、そのリポジトリの `AGENTS.md` に記載する。

英語版は [SKILL.en.md](SKILL.en.md) を参照する。
