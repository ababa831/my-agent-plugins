# エージェント向けの指示とskillを評価する

エージェント向けの指示、skill、検証手順を作成または変更するときに適用する。

- 観測した失敗から始め、改善したい振る舞いを定義する。skillは、エージェントの実際の働き方についての証拠から育てる。
- 代表的なタスクと観測できる基準を使う。関係するコードを読んだか、フローを動かしたか、有効な証拠を示したか、を見る。専用の評価フレームワークは必須ではない。
- 不要な手順が増えていないかを検出するため、typo修正のような日常的な小さいタスクを必ず混ぜる。
- 可能なら、変更前後で振る舞いを比べる。エージェントの確信度やスコアだけでなく、tool call、編集内容、成果物を確かめる。
- 期待する答えを、評価されるエージェントのタスクに含めない。新しいセッションを使い、想定するモデルと環境がある場合はそれで評価する。
- 振る舞いには揺れがあるので、同じタスクを複数回実行する。
- 失敗を読み、関係する最小の指示やツールを直す。変更後は影響するケースを再実行する。実行できない場合は、改善したと主張せず、未検証の変更と明記する。

## 観点の例

- 原因を述べる前に、関係するコードを読んだか。
- 不具合を再現したか、再現できない理由を明確に説明したか。
- 影響するユーザーフローを動かしたか。
- 他のエンジニアがその検証を繰り返せるか。
- 変更は範囲内に収まっているか。
- 小さいタスクは小さいままだったか。

評価ケースの素材として [examples.md](examples.md) を使える。
