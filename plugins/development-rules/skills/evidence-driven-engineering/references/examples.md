# 例

このskillを理解し、評価するためのシナリオ。説明のための例であり、発言の引用や計測に基づく製品の主張ではない。

## ビルドは通るがフローは壊れている

- **タスク:** 項目を開いて戻ると検索フィルタが消える不具合を直す。
- **失敗:** 状態管理を変更し、ビルドを実行して成功と報告する。
- **期待:** 画面遷移の手順を再現し、範囲を絞って修正し、同じ手順を繰り返す。戻った後のフィルタと結果を示す証拠を添える。

## 証拠のない自信ある診断

- **タスク:** 通知が二重に届く原因を調べる。修正はしない。
- **失敗:** 通知経路を読まずに、購読の重複が原因だと断定する。
- **期待:** 発行元、配送経路、受信側をたどる。関係するコードとログを読み、可能なら重複を再現し、裏付けのある所見と仮説を分けて報告する。

## 昨日の回避策が今日の慣習になる

- **タスク:** 固定の待ち時間でリトライしている既存のデータビューの隣に、新しいビューを追加する。
- **失敗:** 近くのコードがそうしているので、待ち時間をそのまま真似る。
- **期待:** 待ち時間がなぜあるのか、新しいビューにも同じ制約があるのかを確かめる。推奨されるデータ取得経路で足りるならそれを使う。無関係な負債は指摘に留め、タスクを広げない。

## レビューのたびに同じ指摘をしている

- **タスク:** 公開エントリーポイントではなく内部実装を import している別のモジュールを直す。
- **失敗:** import を直し、プロンプトに注意書きをもう一つ足す。
- **期待:** import を直したうえで、export、型、lint、CIで再発を防げないかを調べる。新しいチェックは、禁止すべき import と正しい import の両方で確かめる。

## アプリは起動できるが機能にたどり着けない

- **タスク:** 履歴パネルが遅いという報告を検証する。
- **失敗:** アプリを起動し、報告された状態に到達しないままあちこちクリックする。
- **期待:** feature map を使うか、ルートと前提条件を調べる。代表的なデータでパネルに到達し、操作を再現し、適切な計測やトレースを取る。古くなった到達手順は、実際に確認した手順で直す。

## typo修正がフレームワークに育つ

- **タスク:** ドキュメントの見出しのtypoを直す。
- **失敗:** アプリを起動し、検証ツールを作り、周辺のドキュメントまで書き直す。
- **期待:** 見出しを直し、影響するリンクやアンカーを確認し、差分を読む。
